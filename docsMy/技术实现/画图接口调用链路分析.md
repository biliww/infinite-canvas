# 画图接口调用链路分析

> 分析日期：2026-05-29  
> 项目架构：Next.js（前端）+ Go（后端）

---

## 一、整体架构概览

```
用户浏览器（Next.js）
    ↓ axios /api/v1/...
Next.js API Route（代理层）
    ↓ fetch http://127.0.0.1:8080/api/v1/...
Go 后端服务（Gin）
    ↓ 透明代理 + 积分扣费
上游 AI 服务（OpenAI 兼容接口）
```

项目支持四种生成模式：
- **文生图**（Image Generation）
- **图生图**（Image Edit）
- **文本生成**（Chat Completions，流式）
- **视频生成**（异步轮询）

---

## 二、前端层

### 2.1 画布主控制器

**文件**：`web/src/app/(user)/canvas/[id]/canvas-client-page.tsx`

整个画布功能的核心调度器，包含所有生成逻辑的入口函数 `handleGenerateNode`：

1. 调用 `hydrateNodeGenerationContext()` 从上游节点收集参考图片和文本
2. 创建占位节点（`status: loading`）更新 UI
3. 根据模式分发到对应 API（`requestGeneration` / `requestEdit` / `requestImageQuestion` / `requestVideoGeneration`）
4. 接收结果后存入 IndexedDB，更新节点状态

### 2.2 提示词面板（触发点）

**文件**：`web/src/app/(user)/canvas/components/canvas-node-prompt-panel.tsx`

用户在节点上输入 prompt 并触发生成：

```typescript
const submit = () => {
    const text = prompt.trim();
    if (!text || isRunning) return;
    onGenerate(node.id, mode, text);  // 触发生成，mode 由节点类型决定
    setPrompt("");
};
// 支持 Enter 键提交 或 点击按钮提交
// mode: "image" | "text" | "video"
```

### 2.3 上下文构建

**文件**：`web/src/app/(user)/canvas/components/canvas-node-generation.ts`

负责从上游节点收集参考图片和文本，构建生成上下文：

```typescript
buildNodeGenerationContext(nodeId, nodes, connections, prompt)
buildNodeChatMessages(context)
hydrateNodeGenerationContext(context)  // 将 storageKey 转换为 dataUrl
```

### 2.4 渠道模式配置

**文件**：`web/src/stores/use-config-store.ts`

```typescript
// channelMode: "remote" → 走后端代理（默认）
// channelMode: "local"  → 直连 OpenAI 兼容接口
function aiApiUrl(config, path) {
    return config.channelMode === "remote"
        ? `/api/v1${path}`
        : buildApiUrl(config.baseUrl, path);
}
```

## 三、API 服务层（前端）

### 3.1 图片生成

**文件**：`web/src/services/api/image.ts`

#### 文生图 `requestGeneration`

```
POST /api/v1/images/generations
Body: { model, prompt, n, quality, size, response_format: "b64_json" }
```

#### 图生图 `requestEdit`

```
POST /api/v1/images/edits
Body: multipart/form-data（含多张参考图）
```

#### 文本生成 `requestImageQuestion`（流式）

```
POST /api/v1/chat/completions
Body: { model, messages, stream: true }
```

### 3.2 视频生成

**文件**：`web/src/services/api/video.ts`

视频生成为异步轮询模式，分三步：

```
Step1: POST /api/v1/videos        → 提交任务，返回 taskId
Step2: GET  /api/v1/videos/:id    → 轮询状态（2.5s 间隔）
Step3: GET  /api/v1/videos/:id/content → 下载视频 blob
```

## 四、Next.js 代理层

**文件**：`web/src/app/api/[...path]/route.ts`

将所有 `/api/*` 请求透明转发到后端 Go 服务：

```typescript
const apiBaseUrl = process.env.API_BASE_URL || "http://127.0.0.1:8080";
const target = `${apiBaseUrl}/api/${path.join("/")}${search}`;
// 原样转发：请求体、方法、头部
// maxDuration: 300（5 分钟超时，视频生成需要）
```

## 五、后端路由层（Go + Gin）

**文件**：`router/router.go`

```go
v1 := api.Group("/api/v1", middleware.UserAuth)
v1.POST("/images/generations", handler.AIImagesGenerations)  // 文生图
v1.POST("/images/edits",       handler.AIImagesEdits)        // 图生图
v1.POST("/chat/completions",   handler.AIChatCompletions)    // 文本/对话
v1.POST("/videos",             handler.AIVideos)             // 视频提交
v1.GET ("/videos/:id",         handler.AIVideo)              // 视频状态查询
v1.GET ("/videos/:id/content", handler.AIVideoContent)       // 视频下载
```

所有路由均需通过 `UserAuth` 中间件（JWT 鉴权）。

## 六、后端处理层（Handler）

**文件**：`handler/ai.go`

所有 AI 接口使用统一的透明代理函数 `proxyAIRequest`：

```go
func proxyAIRequest(w http.ResponseWriter, r *http.Request, path string) {
    // 1. 解析请求体，提取 model 字段
    body, contentType, modelName, _ := readAIRequest(r)
    // 2. 从 JWT 上下文获取登录用户
    user, _ := service.UserFromContext(r.Context())
    // 3. 查询该模型消耗的积分数
    credits, _ := service.ModelCost(modelName)
    // 4. 加权随机选择上游渠道
    channel, _ := service.SelectModelChannel(modelName)
    // 5. 预扣用户积分
    service.ConsumeUserCredits(user.ID, modelName, credits, path)
    // 6. 构建并转发请求到上游 AI 服务
    req, _ := http.NewRequest("POST", BuildModelChannelURL(channel, path), body)
    req.Header.Set("Authorization", "Bearer "+channel.APIKey)
    // 7. 透传响应（失败自动退还积分）
    copyAIResponse(w, req, refundOnFailure)
}
```

## 七、业务逻辑层（Service）

**文件**：`service/settings.go`

### 渠道选择（加权随机）

```go
func SelectModelChannel(modelName string) (model.ModelChannel, error) {
    // 按模型名称筛选已启用且配置了 BaseURL + APIKey 的渠道
    channels := modelChannelsForModel(settings.Private.Channels, modelName)
    // 按 weight 字段加权随机（weight 越大被选概率越高，实现负载均衡）
    return weightedRandom(channels)
}
```

### 上游 URL 构建

```go
func BuildModelChannelURL(channel model.ModelChannel, path string) string {
    baseURL := strings.TrimRight(channel.BaseURL, "/")
    if !strings.HasSuffix(baseURL, "/v1") {
        baseURL += "/v1"
    }
    return baseURL + path
}
```

## 八、数据存储层

### 8.1 数据库（GORM）

**文件**：`repository/db.go`

支持 SQLite / MySQL / PostgreSQL（通过环境变量 `STORAGE_DRIVER` 配置）：

| 表 | 说明 |
|---|---|
| `users` | 用户信息、积分余额 |
| `credit_logs` | 积分消耗流水 |
| `prompts` | 提示词库 |
| `assets` | 图片/视频素材资产 |
| `settings` | 系统配置（渠道、模型价格等） |

### 8.2 前端本地存储

生成的图片/视频不存入数据库，通过 **localforage（IndexedDB）** 存储在用户浏览器本地：

- `storageKey` 作为引用存在 canvas node 的 metadata 中
- 画布状态（节点、连线）通过 `localStorage` 持久化

## 九、完整调用链路（图片生成）

```
① 用户在节点输入框输入 prompt，点击生成 / 按 Enter
        ↓
② canvas-node-prompt-panel.tsx
   submit() → onGenerate(nodeId, "image", prompt)
        ↓
③ canvas-client-page.tsx: handleGenerateNode()
   - hydrateNodeGenerationContext() 收集上游节点的参考图/文本
   - 创建 loading 占位节点更新 UI
   - 调用 requestGeneration(config, effectivePrompt)
        ↓
④ web/src/services/api/image.ts: requestGeneration()
   POST axios → /api/v1/images/generations
   { model, prompt, n, quality, size, response_format: "b64_json" }
        ↓
⑤ web/src/app/api/[...path]/route.ts（Next.js 代理）
   fetch → http://127.0.0.1:8080/api/v1/images/generations
        ↓
⑥ handler/ai.go: AIImagesGenerations() → proxyAIRequest()
   - JWT 鉴权，获取当前用户
   - 查询模型积分单价
   - 加权随机选择上游渠道
   - 预扣用户积分
   - 转发请求到 {channel.BaseURL}/v1/images/generations
     Header: Authorization: Bearer {channel.APIKey}
        ↓
⑦ 上游 AI 服务（OpenAI / 兼容接口）
   返回 base64 图片数据（b64_json 格式）
        ↓
⑧ canvas-client-page.tsx 接收结果
   - uploadImage(dataUrl) → 存入 IndexedDB
   - 更新节点 metadata（status: success, storageKey）
   - 更新 canvas store → localStorage 持久化
```

## 十、视频生成调用链路（差异点）

```
① POST /api/v1/videos 提交任务（含参考图、参数）
        ↓
② 后端转发到上游 AI 视频服务，返回 taskId
        ↓
③ 前端每 2.5 秒轮询 GET /api/v1/videos/:id
        ↓
④ 状态变为 success 后，GET /api/v1/videos/:id/content 下载视频 blob
        ↓
⑤ 视频 blob 存入 IndexedDB，节点更新为完成状态
```

---

## 十一、文本生成调用链路（差异点）

```
POST /api/v1/chat/completions（stream: true）
        ↓
通过 onDownloadProgress 事件实时接收 SSE 数据流
        ↓
逐字渲染到文本节点（流式效果）
```

## 十二、关键配置项

| 配置项 | 说明 | 位置 |
|---|---|---|
| `API_BASE_URL` | 后端服务地址 | Next.js 环境变量 |
| `STORAGE_DRIVER` | 数据库类型（sqlite/mysql/postgres） | Go 环境变量 |
| `channelMode` | 渠道模式（remote/local） | 前端用户配置 |
| `channel.BaseURL` | 上游 AI 服务地址 | 后端管理员配置 |
| `channel.APIKey` | 上游 AI 服务密钥 | 后端管理员配置 |
| `channel.weight` | 渠道权重（负载均衡） | 后端管理员配置 |
| `ModelCosts` | 各模型积分单价 | 后端管理员配置 |
