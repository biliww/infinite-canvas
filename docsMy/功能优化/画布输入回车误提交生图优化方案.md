# 画布输入回车误提交生图优化方案

## 背景

当前画布里有多个可以输入提示词并触发生图的入口。用户在提示词还没输入完整时，按了一次回车，任务就被提交生图。这类误触在图片生成场景里成本比较高，因为一次提交可能立刻创建节点、请求模型并扣算力点。

本方案分析当前画布前端输入逻辑，并给出优化方向。

## 当前输入和提交逻辑

### 节点生成面板

文件：

```text
web/src/app/(user)/canvas/components/canvas-node-prompt-panel.tsx
```

当前核心逻辑：

```tsx
onKeyDown={(event) => {
    if (event.key !== "Enter" || event.ctrlKey || event.metaKey || event.shiftKey) return;
    event.preventDefault();
    submit();
}}
```

含义是：

```text
普通 Enter：提交生成。
Shift + Enter：不提交，浏览器默认换行。
Ctrl + Enter：不提交，浏览器默认换行。
Command + Enter：不提交，浏览器默认换行。
点击右侧箭头按钮：提交生成。
```

也就是说，用户在这个 `textarea` 里按普通回车，确实会直接提交。

### 画布助手输入框

文件：

```text
web/src/app/(user)/canvas/components/canvas-assistant-panel.tsx
```

当前核心逻辑：

```tsx
onKeyDown={(event) => {
    if (event.key !== "Enter" || event.ctrlKey || event.metaKey || event.shiftKey) return;
    event.preventDefault();
    void onSubmit();
}}
```

含义和节点生成面板一致：

```text
普通 Enter：提交。
Shift / Ctrl / Command + Enter：换行。
点击发送按钮：提交。
```

如果助手处于生图模式，普通回车也会触发生图。

### 文本节点正文编辑

文件：

```text
web/src/app/(user)/canvas/components/canvas-node.tsx
```

文本节点正文编辑的 `textarea` 只处理 `Escape`：

```tsx
onKeyDown={(event) => {
    if (event.key === "Escape") onStopEditing();
}}
```

这里普通回车不会提交生图，而是正常换行。

### 生成配置节点

文件：

```text
web/src/app/(user)/canvas/components/canvas-config-node-panel.tsx
```

生成配置节点主要通过“开始生成”按钮提交，没有看到输入框按回车直接提交的逻辑。

### 其他提交方式

除了输入框回车外，当前画布还存在这些提交方式：

```text
1. 节点生成面板右侧箭头按钮。
2. 画布助手右侧发送按钮。
3. 生成配置节点的“开始生成”按钮。
4. 文本节点上的“生图”按钮。
5. 节点悬浮工具栏里的“生图”按钮。
6. 失败节点悬浮工具栏里的“重试”按钮。
```

其中真正容易误触的是前两类 `textarea` 的普通回车提交。

## 当前问题

### 普通回车语义不符合多行提示词输入

图片提示词经常是多段结构，例如主体、背景、风格、镜头、比例、负面要求等。用户自然会用回车分段。

当前逻辑把普通回车定义为提交，导致：

```text
1. 用户刚输入第一段就提交。
2. 多行提示词输入不顺手。
3. 误提交后会立即创建生成任务，可能扣算力点。
4. 用户需要记住 Shift + Enter 才能换行，学习成本偏高。
```

### 和 `textarea` 默认行为冲突

既然组件使用的是 `textarea`，用户默认预期就是：

```text
Enter 换行。
按钮或明确快捷键提交。
```

当前行为更像聊天输入框，但生图提示词不像短聊天消息，误触成本也更高。

### 中文输入法场景有潜在误触

中文输入过程中，用户可能按回车确认候选词。多数浏览器在输入法组合态会标记 `event.nativeEvent.isComposing`，但当前代码没有判断组合态。

如果某些输入法或浏览器事件顺序异常，就可能在候选词确认时触发提交。即使不是每次都会复现，也应该把组合态保护补上。

## 推荐优化方案

推荐把画布生图相关输入统一改成：

```text
Enter：换行。
Ctrl + Enter：提交。
Command + Enter：提交。
点击箭头 / 发送按钮：提交。
Shift + Enter：继续换行。
输入法组合态：不提交。
```

这样更适合生图提示词，误触成本低，也符合 `textarea` 默认交互。

## 具体改法

### 1. 节点生成面板调整回车逻辑

目标文件：

```text
web/src/app/(user)/canvas/components/canvas-node-prompt-panel.tsx
```

建议从“普通 Enter 提交”改为“Ctrl/Command + Enter 提交”：

```tsx
onKeyDown={(event) => {
    if (event.key !== "Enter") return;
    if (event.nativeEvent.isComposing) return;
    if (!event.ctrlKey && !event.metaKey) return;
    event.preventDefault();
    submit();
}}
```

调整后：

```text
普通 Enter 会走 textarea 默认换行。
Ctrl + Enter / Command + Enter 才提交。
Shift + Enter 仍然换行。
```

### 2. 画布助手输入框保持一致

目标文件：

```text
web/src/app/(user)/canvas/components/canvas-assistant-panel.tsx
```

建议使用同样逻辑：

```tsx
onKeyDown={(event) => {
    if (event.key !== "Enter") return;
    if (event.nativeEvent.isComposing) return;
    if (!event.ctrlKey && !event.metaKey) return;
    event.preventDefault();
    void onSubmit();
}}
```

这样助手问答和助手生图都保持同一套输入习惯。

### 3. 按钮仍作为主要提交入口

右侧箭头按钮保留为显式提交入口。用户想提交时点击按钮，用户想换行时按普通回车，交互边界更清晰。

按钮可以继续使用当前禁用条件：

```text
isRunning || !prompt.trim()
```

### 4. 轻量提示快捷键

如果需要提示快捷键，建议只在输入框附近用很轻的方式展示，例如 placeholder 或按钮 tooltip，不要在页面上增加大段解释。

可选文案：

```text
Ctrl/⌘ + Enter 发送
```

注意：项目规范要求前端页面不要有多余解释，所以如果要加，优先放在按钮 tooltip 或极轻量的辅助文案里。

## 可选增强方案

### 方案 A：仅生图模式改成 Ctrl/Command + Enter

如果担心聊天问答用户习惯“Enter 发送”，可以只对生图模式改：

```text
助手 image 模式：Enter 换行，Ctrl/Command + Enter 提交。
助手 chat 模式：保留 Enter 发送，Shift + Enter 换行。
节点生成面板：Enter 换行，Ctrl/Command + Enter 提交。
```

这个方案兼顾聊天习惯和生图安全，但同一个助手输入框在不同模式下快捷键不同，用户可能仍然困惑。

### 方案 B：首次普通回车只换行并显示轻提示

用户第一次在生图输入框按普通回车时，只换行，不提交，并短暂提示快捷键。

优点是引导明确；缺点是需要新增提示状态，交互稍重。

### 方案 C：提交前短暂可撤销

普通回车仍提交，但提交后先进入 1 秒倒计时，允许撤销。

不推荐第一版采用，因为：

```text
1. 会拖慢正常生成。
2. 需要处理倒计时期间节点状态。
3. 对并发批量生成、扣算力点时机都有影响。
```

## 推荐结论

第一版建议直接采用最小、稳定的改法：

```text
1. 节点生成面板：Enter 换行，Ctrl/Command + Enter 提交。
2. 画布助手输入框：Enter 换行，Ctrl/Command + Enter 提交。
3. 保留右侧按钮作为显式提交入口。
4. 补充 event.nativeEvent.isComposing 判断，避免中文输入法确认候选词时误提交。
```

这个改法范围很小，只涉及两个输入组件，不影响后端，不改变生图请求链路，也不会影响文本节点正文编辑和生成配置节点。

## 需要验证的场景

实现后建议手动验证：

```text
1. 节点生成面板里普通 Enter 可以换行。
2. 节点生成面板里 Ctrl + Enter 可以提交。
3. macOS 上 Command + Enter 可以提交。
4. 中文输入法候选词确认不会提交。
5. 点击箭头按钮仍能提交。
6. 画布助手 chat 模式和 image 模式行为符合最终选择的规则。
7. 正在生成时快捷键和按钮都不会重复提交。
```
