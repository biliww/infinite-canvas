# 生图接口调用链路分析

## 概述

项目目前使用**同步调用**模式对接图片生成接口，前端直接等待接口响应后拿到图片数据（`b64_json` 或 `url`）。整条链路分为三层：前端 API 层 → 后端代理层 → 上游 AI 服务。

---

## 涉及文件

| 层次 | 文件路径 | 职责 |
|------|---------|------|
| 前端 API 封装 | `web/src/services/api/image.ts` | 封装 HTTP 请求、参数构造、结果解析 |
| 生图工作台页面 | `web/src/app/(user)/image/page.tsx` | 独立生图页面入口 |
| 画布助手面板 | `web/src/app/(user)/canvas/components/canvas-assistant-panel.tsx` | 画布内对话式生图入口 |
| 画布主页面 | `web/src/app/(user)/canvas/[id]/canvas-client-page.tsx` | 节点重新生成、批量生成、重试 |
| 后端路由 | `router/router.go` | 注册 `/api/v1/images/*` 路由 |
| 后端 Handler | `handler/ai.go` | 鉴权、扣积分、代理转发上游 |

## 接口清单

| 场景 | 前端请求地址（remote 模式） | 方法 | Content-Type |
|------|--------------------------|------|--------------|
| 文生图 | `/api/v1/images/generations` | POST | `application/json` |
| 图生图 | `/api/v1/images/edits` | POST | `multipart/form-data` |

## 前端 API 层（`web/src/services/api/image.ts`）

### 渠道路由

```ts
function aiApiUrl(config: AiConfig, path: string) {
    return config.channelMode === "remote"
        ? `/api/v1${path}`               // 走本项目后端代理
        : buildApiUrl(config.baseUrl, path); // 直连自定义 API 地址
}
```

`channelMode === "remote"` 时走本项目后端，否则直连用户配置的外部地址。

### 文生图 `requestGeneration`

```ts
// 请求体（JSON）
{
    model: config.model,
    prompt: withSystemPrompt(config, prompt),  // 拼接 systemPrompt 前缀
    n: 1~15,
    quality: "low" | "medium" | "high" | ...,  // 可选
    size: "1024x1024" | "1792x1024" | ...,     // 由 quality+ratio 换算，可选
    response_format: "b64_json",
}
```

### 图生图 `requestEdit`

```ts
// 请求体（multipart/form-data）
model=gpt-image-2
prompt=...
n=1
response_format=b64_json
quality=medium        // 可选
size=1024x1024        // 可选
image=<File>          // 可多个，由 ReferenceImage[] 转换为 File 对象
```

### 尺寸换算逻辑

`config.size` 存储的是比例字符串（如 `16:9`），请求前通过 `resolveSize(quality, ratio)` 换算为像素：

```
quality=low   → basePixels=1024 → 总像素=1024²
quality=medium → basePixels=2048 → 总像素=2048²
quality=high  → basePixels=2880 → 总像素=2880²

按比例分配宽高，取 16 的倍数对齐
例：quality=medium + 16:9 → 约 2720x1536
```

### 结果解析

```ts
// 优先取 b64_json，其次取 url
function resolveImageDataUrl(item) {
    if (item.b64_json) return `data:image/png;base64,${item.b64_json}`;
    if (item.url)      return item.url;
    return null;
}
// 返回 [{id: nanoid(), dataUrl: string}]
```

## 后端代理层（`handler/ai.go`）

所有生图请求都走统一的 `proxyAIRequest`：

```
前端请求
   │
   ▼
readAIRequest()
   │  解析 body，提取 model 字段
   │  JSON → payload.Model
   │  multipart → form["model"]
   ▼
service.ModelCost(modelName)
   │  查询该模型的积分消耗单价
   │  乘以请求数量 n → 总积分
   ▼
service.SelectModelChannel(modelName)
   │  根据模型名选择上游渠道（baseURL + APIKey）
   ▼
service.ConsumeUserCredits(userID, modelName, credits, path)
   │  扣除积分，扣失败直接返回错误
   ▼
http.DefaultClient.Do(request)
   │  代理转发至上游 AI（如 chatgpt2api 的 /v1/images/generations）
   │  上游返回 4xx/5xx → 退款 RefundUserCredits → 返回错误
   ▼
copyAIResponse()
   │  将上游响应头、响应体直接透传给前端
   │  前端收到 { data: [{b64_json: "..."}] }
```

**关键特性：**
- 上游请求失败自动退款，不会吃掉用户积分
- 响应直接透传，不做任何内容转换
- 不支持流式返回（图片接口本身不需要）

## 三个前端调用入口

### 入口 1：生图工作台（`image/page.tsx`）

```
用户点击"开始生成"
  → generate()
    → buildRequestSnapshot()   // 收集 {text, config, references}
    → 并行启动 N 个生成槽 runGenerationSlot()
        → 有 references → requestEdit()
        → 无 references → requestGeneration()
        → 拿到 [{id, dataUrl}]
        → readImageMeta()      // 读取图片宽高
        → uploadImage(dataUrl) // 存入 IndexedDB
        → setResults()         // 更新页面展示
    → saveLog()                // 写入 localforage 历史记录
```

### 入口 2：画布助手面板（`canvas-assistant-panel.tsx`）

```
用户在助手输入框发送消息（mode="image"）
  → sendMessage(text, "image", history)
    → 取当前选中节点的图片 → imageToDataUrl() → ReferenceImage[]
    → 有参考图 → requestEdit()
    → 无参考图 → requestGeneration()
    → uploadImage(dataUrl)
    → updateMessage()          // 更新对话气泡，展示图片
    → onInsertImage(image)     // 可选：插入画布节点
```

### 入口 3：画布节点操作（`canvas-client-page.tsx`）

三处节点级操作，均调用同一套接口：

| 操作 | 触发方式 | 参考图来源 |
|------|---------|-----------|
| 重新生成/变体 | 节点右键菜单 | 当前节点图片 |
| 批量生成 | 多节点批量操作 | 选中节点图片（可选） |
| 重试 | 节点重试按钮 | 原始参考图 |

生成完成后均调用 `uploadImage(dataUrl)` 持久化，再更新节点 `metadata`（dataUrl、storageKey、width、height）。

## 完整数据流图

```
用户操作
   │
   ▼
前端组件（image/page.tsx / canvas-assistant-panel.tsx / canvas-client-page.tsx）
   │  收集：prompt、model、quality、size（比例）、count、references[]
   │
   ▼
web/src/services/api/image.ts
   │  resolveRequestSize()  比例 → 像素尺寸
   │  withSystemPrompt()    拼接 systemPrompt
   │  有 references → requestEdit()   → POST /api/v1/images/edits   (multipart)
   │  无 references → requestGeneration() → POST /api/v1/images/generations (JSON)
   │
   ▼
后端 handler/ai.go
   │  readAIRequest()       解析 model、body
   │  ModelCost() × n       计算积分
   │  ConsumeUserCredits()  扣积分
   │  SelectModelChannel()  选渠道（baseURL + APIKey）
   │  代理转发上游 AI
   │  失败 → RefundUserCredits()
   │
   ▼
上游 AI 服务（如 chatgpt2api /v1/images/generations）
   │  返回 { data: [{b64_json: "..."}] }
   │
   ▼
后端透传响应
   │
   ▼
前端 parseImagePayload()
   │  → [{id: nanoid(), dataUrl: "data:image/png;base64,..."}]
   │
   ▼
uploadImage(dataUrl)        → IndexedDB 持久化
setResults() / setNodes()   → 页面渲染 / 画布节点更新
```

## 当前方案的局限性

| 问题 | 说明 |
|------|------|
| 同步阻塞 | 前端 axios 请求会一直等待，图片生成期间（10~60s）无法中断 |
| 超时风险 | 浏览器、Nginx、后端代理均有超时限制，长时间生成可能断连 |
| 无法重试 | 请求一旦失败，积分已退但任务状态无法查询，需重新发起 |
| 无队列管理 | 多个并行槽同时发起请求，无法感知服务端排队状态 |
